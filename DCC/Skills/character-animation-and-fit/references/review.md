# 回放、证据与结果措辞

## 三类验收分别判断

| 类型 | 必须观察 | 不能替代它的证据 |
|---|---|---|
| 表演 | 正常速度下动作目的、重心、节奏、先后、姿态、手势及结束收势 | 编译、角度范围、IK 目标误差 |
| 形体/接触 | 当前目标引擎中相关视角的关节、掌指抓握、脚支撑、衣料层次和抽脚全过程 | 一张站立截图；只测试透明遮罩后的相交 |
| 技术 | 源身份、导入、约束顺序、无跳变、布料时序、暂停重播、设备性能 | DCC 中效果正常；静态材质还原 |

各项用“通过 / 失败 / 待验证”，并写具体原因。没有审阅视频的艺术质量就只能待验证，不允许把技术通过转写成“动画合理”。

## 实际录像

记录资产/版本、角色、采样率、视角、时间范围、时间单位、运行设置。先确认是真正导入当前修改的实例。主视角正常速度连续播放完整动作；补侧面、手部和脚部近景。摄像机不能遮掉问题，也不能为了拍证据让玩家视角更难使用。

以实际连续求值的渲染帧按原时间顺序编码视频；帧号缺失和模拟中途重置必须报告。记录是否实时捕获或离线固定步长渲染。稀疏关键帧仅用来审阅形状，不能通过插帧/幻灯片称为正常动画。

正常速度先看整体意图、动作停顿和结束姿态，再在接触转换附近逐帧看手指、鞋头、袜口、脚跟。用纯色/线框、关遮罩诊断和最终材质画面分别判断；几何穿插与画面可见性分别报告。

只有截图时仍可指出确定的形体和姿态问题，但不要推断动态节奏通过。截图接触无法看到拇指时写“抓握不可判断”，不按指尖坐标误差替代肉眼观察。

## 量化检查的适用边界

记录单位、参考点、求值阶段、采样密度、覆盖范围和排除条件。接触应比较独立的掌/指标记与物体局部抓点；若物体又被强制移到手上，相交或距离为零可能是循环定义，不能证明可达性。脚跟、前掌等高不自动等于正常站姿或正确足底贴地。

穿插测试区分表面相交、体积包含和时域漏检；必要时在风险区加密或做连续检测。碰撞 skin offset、袜层厚度、屏幕可见尺寸和制作容差有实际依据时才设阈值，失败后不能只放宽阈值。

## 对照板工具

输入是人工选择的现有本地图像。JSON 清单：

```json
{
  "title": "Triss / baseline contact review",
  "evidence_kind": "sparse_keyframes",
  "fps": 30,
  "frames": [
    {"path": "C:/Project/Artifacts/389-front.png", "label": "Triss", "frame": 389, "view": "front"},
    {"path": "C:/Project/Artifacts/390-feet.png", "label": "Triss", "frame": 390, "view": "feet"}
  ]
}
```

执行：

```text
python scripts/contact_sheet.py manifest.json review.png --columns 3 --width 480
```

`fps` 只把帧号转成采样时间；不推测角色状态机的相对时间。`evidence_kind` 支持 `sparse_keyframes` 或 `continuous_frames`；连续帧模式要求同一视角、同一角色的连续帧号，此检查只证实清单连续，不能证明录制真实或动作流畅。输入路径相对清单目录解析。此工具使用 Pillow；仅改变输出板上的缩放，不修改源图。

## 最小镜头记录

1. 镜头意图、目标视角、用户约束。
2. 参考来源与查看范围、动作机制的不确定项。
3. 身体/服装来源、关键改动及备份。
4. 节拍表、姿态和接触状态。
5. 观察到的失败点：角色、帧/时间、视角、现象；判断与推断分开。
6. 修复顺序及小范围执行结果。
7. 三类验收结果、实际证据链接与剩余问题。

无法运行引擎、查看源图或访问参考时仍完成可以做的诊断，并说明对应局限；不要伪造“验证完成”，也不要反复要求用户确认可逆步骤。
